# Relight Anime の作り方

[English](how-it-works.en.md) ｜ [README](../README.md) ｜ 細かい設計と経緯: [設計.md](設計.md)

Relight Anime は、AI で作ったアニメ動画（完成済みの RGB 動画）に、あとから光と影を足す After Effects のエフェクトです。
この文書は「どう作ってあるか」と「一から作るときの手順」をまとめたものです。

---

## 1. 全体の流れ

```
素材レイヤーに Relight Anime を付ける
  │
  ├─ 深度を作る（1 回だけ。結果は cache/ に残る）
  │    AE に素材のフレームを描かせる → relight_depth.exe（ONNX Runtime + CUDA）で深度を推定
  │    または、別の PC の深度サーバーに動画を送って作らせる（Depth Engine = Remote）
  │    → 16bit の深度 PNG を読み込み、非表示のレイヤー「Relight depth」として結線する
  │
  └─ 照明を計算する（毎フレーム）
       深度から 面の向き・凹み・落ち影 を求め、光源ごとに光を当て、元の絵に光と影を足す
       CPU 版と GPU 版（CUDA）が同じ計算の部品（RelightCore.h）を使う
```

深度の推定を AE の描画の外に出しているのは、AE がフレームを任意の順番で、しかも並列に要求するのに対し、
動画の深度推定は前後のフレームをまとめて処理しないと時間方向に安定しないためです。

## 2. 深度を作る

### 2.1 モデル

- **Video Depth Anything Small**（Apache-2.0）を使います。前後のフレームをまとめて見る動画用の深度モデルで、1 枚ずつ推定するモデルより時間方向に安定します。
- `tools/export_vda_onnx.py --split` で、モデルを **エンコーダ（DINOv2）** と **ヘッド（時間方向）** の 2 つの ONNX に分けて書き出します。
  - エンコーダは 1 フレームずつ独立なので、4 フレームずつ通します（32 フレームを一度に通すと VRAM 32GB を使い切りました）。
  - ヘッドは 32 フレームの窓ごとに通します。

### 2.2 relight_depth.exe（`depth/relight_depth.cpp`）

Python も ComfyUI も使わない、単体の C++ プログラムです。ONNX Runtime の DLL を実行時に読み込みます。

1. AE が書き出したフレーム（`frames.bin`、短辺 518px 以上に縮小）を読む
2. 元の実装と同じ窓の進め方で推定する
   - 32 フレームの窓を 22 フレームずつずらし、先頭 10 枠には前の窓のキーフレームを入れる（その特徴は使い回す）
   - 窓ごとの出力を、前の窓のキーフレーム 2 枚に最小二乗でスケール合わせし、重なり 8 フレームは線形に混ぜる
3. **時間方向のならし**（ちらつき対策。§5）
4. **ショット全体の 2%〜98%** で 0..1 に正規化し（近い = 1）、16bit グレーの PNG に書く
5. CUDA で失敗したら、AE に同梱の ONNX Runtime（DirectML）でやり直す

### 2.3 別の PC で作る（Depth Engine = Remote）

`tools/depth_server/depth_server.py` は、深度だけを作る小さな HTTP サーバーです（ComfyUI 不要）。
動画を `POST /depth` で受け取り、Video Depth Anything の公式コードで推定し、正規化と時間方向のならしまで GPU で済ませて返します。
systemd のソケット起動で、依頼が来たときだけ起動し、5 分使われなければ自分で終わります。
エフェクトの **Depth Engine** で、Local GPU / Remote Fast（小さいモデル）/ Remote Quality（大きいモデル）を選べます。
届かないときはこの PC で作り直します。設置の手順は [tools/depth_server/README.md](../tools/depth_server/README.md)。

## 3. 照明の計算（TypeGPU の作例の移植）

照明モデルは、TypeGPU の作例「Monocular Light Injection」（Software Mansion、MIT）を C++ に移植したものです。定数と式は原典のままです。

| 処理 | 内容 |
|---|---|
| 面の向き | 深度の前後差のうち小さい方に寄せた勾配（7 texel）。ノイズ分を引き、tanh で上限を付ける |
| 凹み | 半径 3 / 9 texel の周り 16 点で、手前に出ている深度を数える |
| 落ち影 | 光源の方向へ 32 歩レイマーチする |
| 照明 | 元の色 × 環境光 × 凹み ＋ 光の色 × 巻き込み Lambert × 距離の減衰 × 影 × 強さ ＋ 照り返し |
| 光の玉 | 半径 0.05 の球。手前の物に隠れ、周りににじみを描く |
| 仕上げ | 輝度ベースのフィルム風トーンマップ |

原典は正方形の映像を 448×448 の深度で扱うので、任意のアスペクト比に広げました。
uv は `u = 0.5 + (px − W/2) / H`、`v = py / H`、1 texel は `H / 448` ピクセルです。
深度・勾配・凹み・落ち影・当たり具合は「画面の高さ = 448 マス」の格子で先に計算し、各画素では補間します。

## 4. アニメ向けに足したもの

原典はカメラ映像向けで、元の絵を一律に暗くしてフィルム風に丸めるため、アニメの鮮やかな色がくすみます。
Look = Anime（既定）では次のようにしています。Look = Cinematic にすると原典と同じ式になります。

| 機能 | 作り方 |
|---|---|
| Look = Anime | 元の色を暗くせず、光の届かない側に影色を乗せ、届く側に光を足す。明るすぎる所だけ色相を保って丸める |
| 撮影寄りの陰影 | 画面上で光源からの距離のなめらかなグラデーション（撮影の「パラ」のような光）。面の細かい向きを使わないので時間で揺れない。立体的な陰影とは Form Shading の割合で混ぜる |
| セル調 | 当たり具合を段に分け、境目をぼかす |
| 線画の保護 | 暗く、周りより暗い細い所を線とみなし、元の色に戻す。黒髪のような広い暗部は外れる |
| 深度の膨らみ | 実写で学習した深度モデルはアニメの人物を平たく推定しがちなので、輪郭からの距離に応じて手前に盛り上げる |
| 深度を線画に合わせる | 深度（短辺 518px）を素材の大きさへ伸ばすとき、素材の色が近い点を重く見る（joint bilateral upsampling）。深度の境目が線画に沿う |
| 光源 3 灯 | 光源ごとに位置・高さ・色・強さ・範囲（Range）・光の玉の表示・リムの設定を持つ |
| リムライト | 下の §4.1 |

### 4.1 リムライト

撮影でリムライトや透過光を作るときの定番「**マットを光源の方へずらして引く**」を、深度でやっています。

1. 画素から光源の向きへ、リムの幅の中で 6 点ずらして深度を見て、ずらした先が十分奥（物の外）になる割合を帯の下地にする
2. 逆光のときは、輪郭の外向きと光源の向きで光らせる範囲を絞る（Rim Spread）。画面上で光源から遠い輪郭ほど弱める（Rim Reach）
3. 下地を少しぼかし、ぼかす前の下地が無い画素は消す（輪郭の外へにじませない）
4. 深度の境目が線画より外へずれた隙間には帯を作らない（人物の輪郭線の外へ光を出さない）
5. **Rim Smoothing**：帯を作る前に、深度に中央値フィルターを掛ける。段差は保ったまま、半径より小さいでこぼこ（深度推定の細かい揺れ、粗い解像度の階段）だけが消えるので、帯の線がなめらかになる。ぼかしと違って奥行きの差が薄まらず、何段も重なった所で差を大げさにしない
6. リムが乗る画素では、線画の保護は線の芯だけを守る（輪郭線の半端な縁まで守ると、帯が細かく欠けてガタガタに見えた）

以前は 1 画素ずつ輪郭を探して距離を測っていましたが、判定が少し揺れるだけで帯の幅が段になり、ビーズのように切れて見えました。

## 5. 動画でちらつかせない工夫

深度の推定は、キャラが動いていなくてもフレームごとに少し揺れます。その揺れを照明が明るさの揺れに変えると、ろうそくの炎のように見えます。
特にライトを人物の後ろに低く置くと、「光の当たる側／裏側」の判定とセル調の境目で増幅されます。

| 工夫 | 内容 |
|---|---|
| ショット全体で正規化 | 原典は各フレームの範囲で正規化して時間方向に追従させるが、動画ではショット全体で 1 つの範囲にする |
| 深度を作るときの時間方向のならし | 元の絵の色が変わっていない画素だけ、前（後ろ）のコマのならした深度を 0.9 の割合で残し、前向きと後ろ向きを平均する。動いている所は色が変わるので混ぜない（残像にならない） |
| 撮影寄りの陰影を主にする | 揺れやすい面の向きの割合を Form Shading（既定 0.25）に抑える |
| Depth Stabilize | 前後 ±2 フレームの深度の中央値。1〜2 フレームだけ飛び出す値が消える |

揺らぎは、オプティカルフロー（DIS）で前のコマを今のコマの位置へずらしてから比べて測っています（`tools/harness/flow_flicker.py`）。
同じ画素どうしで比べると、キャラが動いた分まで揺らぎに数えてしまうためです。
人物の後ろの低いライトで、揺らぎの最大値は 0.014 → 0.009（ならし）、大きいモデル（Remote Quality）で 0.003 になりました。

## 6. 速さ（CPU 版と GPU 版）

- 照明の計算は `plugin/src/RelightCore.h` にまとめ、関数はすべて CPU と CUDA（`__host__ __device__`）の両方で動きます。
- 全体の手順は、CPU 版（`RelightAE.cpp`、作業スレッドで行ごと）と GPU 版（`RelightGPU.cu`、カーネルで 1 画素・1 マスずつ）がそれぞれ持ち、同じ関数を呼びます。差は 8bit で最大 1 段です（`tools/harness/compare_gpu.py`）。
- AE の GPU の描画（`PF_Cmd_SMART_RENDER_GPU`）では、入力・出力・深度のワールドが GPU のメモリ（BGRA float）で渡るので、そのまま使います。作業領域は使い回し、フレームごとに確保しません。
- 1376×768 で GPU 約 1〜3 ms、CPU 約 50 ms（RTX 5090 / 24 スレッド）。

## 7. AE に組み込むときの注意

| 事柄 | 対応 |
|---|---|
| フレームの順番 | AE は任意の順・並列にフレームを要求する。深度の推定は描画の外（別プロセス）で行う |
| 深度の自動生成 | エフェクトから登録したアイドルフックは呼ばれず、タイマーから AEGP を呼ぶと AE が落ちた。補助 AEGP（`RelightAnimeHelper.aex`）のアイドルフックから処理する |
| キャッシュ | 素材のファイル名・場所・大きさ・更新日時から決める。同じ素材の処理中のジョブには相乗りする |
| パスの形式 | 16bit PNG（色管理なしで値がそのまま届く）。EXR は Preserve RGB が要る |
| 入力 | premultiplied。非乗算に戻して計算し、元の色と混ぜてから掛け戻す |
| パラメータの追加・並べ替え | パラメータ ID を固定して、保存したプロジェクトの値を引き継ぐ（例: リムを光源ごとに移したとき、Light 1 は以前の ID を使った） |
| GPU | CUDA のときだけ GPU 可と返す。ほか（DirectX など）は CPU 版 |
| コンポビュー | 光源ごとに光の色の輪・番号・高さ・範囲の目安（点線の輪）を描く。位置のドラッグは AE 標準の 2D ポイントのハンドルに任せる |

## 9. 一から作る手順

必要なもの: Windows 11、After Effects 2025 以降、Visual Studio 2022 Build Tools（C++）、CMake、Ninja、CUDA Toolkit 12.x、Python（モデルの書き出し用）、After Effects SDK。

1. **AE SDK** を https://developer.adobe.com/after-effects/ から入手して展開する（リポジトリには含めていない）
2. **ONNX モデル**を作る: `python tools/export_vda_onnx.py --split`（`models/` に出る。重みは `video_depth_anything_vits.pth`）
3. **深度推定プログラム**をビルドする: `.\depth\build.ps1`
4. **プラグイン**をビルドして入れる（管理者権限）:
   `.\plugin\build.ps1 -SdkRoot <SDK の場所> -Install`
   - `%APPDATA%\SRLM\RelightAnime.ini` に、推論プログラム・モデル・ONNX Runtime・CUDA の DLL の場所を書く（無い項目だけ追記）
   - CUDA 版 ONNX Runtime と cuDNN の DLL の場所は PC ごとに違うので、設定ファイルの `ort` と `dll_dirs` を確かめる
5. （任意）別の PC で深度を作るなら、[tools/depth_server/README.md](../tools/depth_server/README.md) のとおりに設置し、`-RemoteServer <URL>` を付けてビルドする
6. AE で素材のレイヤーに「SRLM > Relight Anime」を付ける。深度ができると自動で結線される

## 11. 既知の限界

- 元の絵に焼き込まれた影は消えない（暗くして上から光を足す方式のため）
- 深度の背景が遠い壁として扱われ、大きな落ち影が出ることがある（Shadow で調整、Mask Layer で範囲を限定）
- 時間伸縮・タイムリマップしたレイヤーには深度が追従しない。深度ができた後にレイヤーを複製して別の時刻へ動かすと、複製は元の深度レイヤーを参照するのでずれる
- 光源は 3 灯まで

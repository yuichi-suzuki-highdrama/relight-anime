# Relight Anime 設計書

AI アニメ素材（完成済み RGB 動画）を After Effects 上で再照明するプラグイン。

## 1. 方針

| 段階 | 内容 | 状態 |
|---|---|---|
| 第一段階 | 深度パスを自動生成し、TypeGPU の作例と同じ照明モデルで AE 内で光を注入する | 実装済み。深度推定は Python / ComfyUI 不要の relight_depth.exe（2026-10-07）。AE 内での通し確認は未 |
| 第二段階 | 生成型リライト（LiveLight など）を「生成モード」として別枠で統合する。照明の変化だけを原画に乗せる | 見送り（2026-10-07）。GPU 負荷が大きく、検証中にブレーカーが落ちた |

経緯（2026-10-07）:

- 最初は法線パスに Lambert で「光を足す」方式だったが、アニメ素材では元の影が焼き込まれているため変化が弱く、「リライトされた感じがない」と評価された。
- TypeGPU の作例「Monocular Light Injection」（Software Mansion、MIT）が同じ深度方式で強い効果を出していたため、その照明モデルを移植した。
  差は照明の作り方にあった。元映像を暗くしてから強い点光源を当て、深度のレイマーチで落ち影を付け、光の玉を描き、トーンマップで丸めている。
- 推論を AE のレンダー関数の外に出す理由は変わらない。AE はフレームを任意順・並列に要求するが、動画の深度推定は前後フレームをまとめて処理する。

## 2. 全体構成

```
素材レイヤーに Relight Anime を適用
   │  PF_Cmd_SEQUENCE_SETUP / RESETUP → Auto_Request
   ▼
RelightAuto (補助 AEGP RelightAnimeHelper.aex のアイドルフックから RelightAnime_Idle が呼ばれて処理する。エフェクトから登録したアイドルフックは呼ばれず、WM_TIMER から AEGP を呼ぶと「no current context」で AE が落ちたため。WM_TIMER は進み具合の窓の更新だけ)
   │  素材のファイルパスを取得 → キャッシュキー (ファイル名 + パス/サイズ/更新日時のハッシュ)
   │  同じ素材の処理中ジョブや、前のセッションで動いている推論があれば相乗りする (2 重に推論しない)
   │  キャッシュがなければ、AE に素材を 1 フレームずつ描かせて frames.bin に書く
   │  (短辺 518px 以上に縮小、1 回 120 ms で区切って UI を止めない)
   ▼
depth/relight_depth.exe (別プロセス、優先度は通常より低め)
   │  ONNX Runtime 1.23 + CUDA。失敗したら AE 同梱の ONNX Runtime (DirectML) でやり直す
   │  Video Depth Anything Small をエンコーダとヘッドの 2 つの ONNX に分割:
   │    エンコーダ (DINOv2) は 4 フレームずつ通す。32 フレームを一度に通すと VRAM 32GB を使い切った
   │    ヘッド (時間方向) は 32 フレームの窓ごと。窓の処理は元の実装と同じ
   │      (22 フレームずつずらし、先頭 10 枠は前の窓のキーフレーム。その特徴は使い回す。
   │       キーフレーム 2 枚で最小二乗のスケール合わせ、重なり 8 フレームは線形に混ぜる)
   │  深度をショット全体の 2%〜98% パーセンタイルで 0..1 に正規化し、16bit グレーの PNG に (WIC)
   ▼
cache/<キー>/ depth/depth.%05d.png, manifest.json, status.json, gen.log (frames.bin は成功後に消す)
   │
   ▼  RelightAuto: 連番をプロジェクトへ読み込み、コンポに非表示・シャイのレイヤーとして追加し、
   │              フレームレートを素材に合わせ、Depth Layer に結線
   │  (旧方式 engine=comfyui は tools/gen_passes.py + ComfyUI で、深度と法線を作る)
   ▼
Relight Anime エフェクト (RelightAE.cpp)
   深度を float バッファに展開 → 画素ごとに勾配・凹み・落ち影・照明・光の玉を計算
```

## 3. 照明モデル（TypeGPU からの移植）

原典: `apps/typegpu-docs/src/examples/image-processing/monocular-light-injection/shaders.ts`。定数と式は原典のまま。
2026-10-07 時点で GitHub 最新版とシェーダは同一（差分は meta.json の説明文のみ）。

| 処理 | 内容 |
|---|---|
| 深度の範囲 | 原典は各フレームの 2%〜98% を範囲にして時間方向にゆっくり追従させる。動画ではショット全体で 1 つの範囲にする（追従を止めた状態と同じで、ちらつかない） |
| 面の向き | 深度の前後差のうち小さい方に寄せた勾配（7 texel）。ノイズ分を引き、tanh で上限。Relief × 200 倍して傾きにする |
| 凹み | 半径 3 / 9 texel の周囲 16 点で、手前に出ている深度を数える |
| 落ち影 | 光源方向に 32 歩レイマーチ。受け手の傾きに応じたバイアス、厚み、光源より手前の遮蔽物の除外 |
| 照明 | albedo × 環境色 × Ambient × 凹み ＋ albedo × 光の色 × 巻き込み Lambert × 距離減衰 × 影 × 強さ ＋ 照り返し |
| 光の玉 | 半径 0.05 の球。手前の物に隠れる。周りに halo と veil のにじみ |
| 仕上げ | 輝度ベースのフィルム風トーンマップ（白点 2.6）→ ガンマ 2.2 で表示色へ |

原典の既定値（プリセット Cinematic (TypeGPU)）: Ambient 0.5、Intensity 3、Relief 0.85、Specular 0.22、Shadow 0.7、Occlusion 0.55、光の色 (1, 0.72, 0.46)、高さ 0.42。
v2.1 からパラメータの既定値はプリセット Anime Standard。

### 座標の拡張

原典は正方形に切り抜いたカメラ映像を 448×448 の深度で扱う。AE の素材は任意のアスペクト比なので、次のように拡張した。

| 項目 | 規約 |
|---|---|
| uv | u = 0.5 + (px − W/2) / H、v = py / H。縦は 0..1、横は高さ比で伸びる |
| 1 texel | H / 448 ピクセル。勾配と凹みのサンプリング距離はこれに比例するので、解像度が変わっても見た目が同じ |
| z | カメラ側が正。最も手前の面が 0、最も奥が −0.7（影の計算では −1.25） |
| 光源 | Light Position（2D ポイント、ドラッグ可）を uv に変換。Light Height は −0.6〜1.65 |
| 光の玉の輪郭 | 原典の fwidth を解析的に計算 |

### アニメ向けの拡張（v2.1、2026-10-07）

原典はカメラ映像向けで、元の絵を一律に暗くしてフィルム風トーンマップを掛けるため、アニメの鮮やかな色がくすむ。
次を足した。Look = Cinematic で影色・セル・リム・線画の保護・膨らみを 0 にすると原典と同じ式になる（プリセット Cinematic (TypeGPU)）。

| 処理 | 内容 |
|---|---|
| Look = Anime | 元の色 × 環境色 × Ambient × 凹み × 影色 ＋ 光 × 0.4。0.85 より明るい所だけ色相を保って丸める（元の色はそのまま通る） |
| 当たり具合 | 光源ごとに「面の向き (wrapped) × 落ち影 × 光の届く範囲 (減衰 × 1.2 を 0..1 に)」。光源の中で最大のものを使う |
| 影色 | 当たり具合が 0.25〜0.6 を下回る所に Shadow Color を乗算で混ぜる（表示色で掛けたのと同じになるようリニアで）。白い服のように光を足しても変わらない所でも光の届く範囲が見える |
| セル調 | 当たり具合を Cel Steps 段に分け、Cel Softness で境目をぼかす。Cel Shading で元のなめらかな値と混ぜる |
| リムライト | 画素ごとに、光源の方へ進んで輪郭（この画素より 0.04 以上奥へ落ちる所）までの距離を測り、Rim Width の内側を帯にする（境目は補間して小数で求め、端は 1px でなめらかに）。All Around は 8 方向で輪郭全体を測り、光源側ほど強くする。Auto は光源が手前なら光源の側だけ 0.6 倍、物の後ろなら輪郭全体を 1.5 倍。最初は格子で縁を探していたが、帯の太さと形が深度のギザギザに引きずられて「アニメにはきれいでない」と言われたため、画素単位に変えた。近くに輪郭が無い画素は、格子の「周りで最も奥の深度」で先に飛ばす。後ろとの深度差が 0.04〜0.18 の輪郭 (フリルの段・手前の脚とスカートなど物の内側の重なり) は弱め、0.18 以上 (背景に対する外側の輪郭) で最大。逆光で内側の重なりまで光らせると白い線だらけで汚く見えたため。さらに現実の逆光に合わせ、輪郭の外向きと光源の向きの内積で光らせる範囲を絞り (Rim Spread、0 = 光源を向いた側だけ)、画面上で光源から遠い輪郭ほど弱める (Rim Reach)。上に光源があるとき、スカートの下の縁のように光源と反対を向き、光源から遠い輪郭は光らない |
| 線画の保護 | 輝度が Line Threshold より暗く、周り (1080p で半径 4px の箱形平均) より 0.02 以上暗い所を線とする。広い暗部（黒髪）は周りと同じ暗さなので外れる。最後に元の色へ戻す（光の玉の上は除く） |
| 深度の膨らみ | 格子で隣と 0.02 以上違うマスを輪郭とし、輪郭からの距離 (面取り距離変換) で 40 マスかけて最大 0.08 × Depth Volume だけ手前に盛り上げる。手前の物ほど強く (深度 0.25〜0.7)、背景は平らのまま |
| 複数光源 | 最大 3 灯。落ち影は光源ごとに格子で計算する（1 灯増えるごとに約 +10 ms @1344x768） |
| 逆光 | Light Height < 0 のとき、にじみを画素ごとに「この面より光源が手前か」で出す。人物の周りの背景だけが光る |
| 深度の引き伸ばし | 深度は短辺 518px。素材の大きさへバイリニアで伸ばす（以前は最寄りの 1 点で、境目が階段になっていた）。Snap Depth To Lines がオンなら、深度が変わる所だけ周り 4x4 の点を「その位置の素材の色がこの画素の色に近いほど」重く見て混ぜる（joint bilateral upsampling）。アニメは線画と塗り分けがはっきりしているので、深度の境目が線画に沿う。1344x768 で約 3 ms |
| 補助レイヤーの位置 | 深度・法線・マスクのレイヤーは全体を取り出し、素材レイヤーの中の位置の割合で対応させる。以前は素材の描く範囲をそのまま補助レイヤーにも渡していたため、拡大表示で一部だけ描くときに深度がずれていた |
| 輪郭のディザ | Edge Dither。深度の傾きが大きい所 (輪郭) だけ、効果 (照明後 − 元の絵) を輪郭に沿う向き (傾きに直交) に ±Edge Dither × 4px (1080p) の範囲で平均し、読み取り位置を画素ごとにずらす。横切る向きにはぼかさないので縁の切れ味は残る。周りの画素を見るため、この経路では iterate を使わず全体を浮動小数で描いてから書き出す。1344x768 で約 +10 ms |
| 当たり具合の格子 (セルシェーダー式) | Shade Smoothness > 0 のとき、光源ごとの当たり具合 (面の向き × 落ち影 × 光の届く範囲) を格子で求め、深度が近いマスどうしで Shade Smoothness × 16 マスの半径でならしてから、画素でセル調のしきい値に掛ける。3D のセルシェーダーと同じく、なめらかな値を一本のしきい値で分けるので境目がきれいな曲線になる。画素ごとに求めてから段に分けていたときは、深度のざらつきがまだらの段になっていた (逆光で光源が背景の壁に近いと特にひどかった)。ならすときは落ち影のレイマーチの揺らぎも止める |
| 並列処理 | 使い回しの作業スレッド (CPU の数 − 1 本) を全フレームで共有する。以前は呼ぶたびに 16 本作っていたため、AE が複数フレームを同時に描くと奪い合い、AE で 1 フレーム 300〜550 ms (確認用ツールでは約 60 ms) かかっていた |
| 陰影のならし | Shade Smoothness × 12 マスの半径で、面の向き・凹み・落ち影を、深度が近いマスどうしだけで縦横にならす。服のしわなど深度の細かい凹凸を拾うと拡大時にまだらで汚く見えるため。撮影でかぶせる影のように、トーンが均一で境目にボケ足がある陰影になる |
| 格子の補間 | 周りの 4 マスが輪郭をまたぐときは、手前組と奥組の値を画素の深度で混ぜる（重み付き平均だと格子の段が見えた） |

プリセットは RelightAE.cpp の PRESETS 表。0 番 (Anime Standard) がパラメータの既定値を兼ねる。
選ぶと PF_Cmd_USER_CHANGED_PARAM で各パラメータを書き換え、ポップアップは Select... に戻す。

### 撮影寄りの陰影と揺らぎ対策 (2026-10-08)

動画で影が揺らぐという指摘を受けて測った (tools/harness/flicker_test.py、逆光の場面で連続 8 フレーム)。
一番の原因は「影色を乗せる所」の判定で、深度の傾きから作った面の向きにしきい値を掛けていたため、
深度推定のフレームごとの小さな揺れが大きくなって見えていた。

アニメの制作では、キャラの影は仕上げで硬い 1〜2 段に塗られ (AI の素材にもすでにある)、
撮影 (AE の後処理) ではパラ・透過光・入射光などのグラデーションを足す。撮影のグラデーションは
大きく・なめらかで・時間で揺れず・元の塗りと喧嘩しない。そこで既定を撮影寄りにした。

| 処理 | 内容 |
|---|---|
| 撮影寄りの当たり具合 (para) | 画面上で光源からの距離 (Light Spread で広がり) のなめらかなグラデーション。光源が物の後ろなら、その物 (手前) は暗い側 (× 0.2)。面の細かい向きを使わない |
| 立体的な当たり具合 (form) | 原典の考え方 (面の向き × 落ち影 × 光の届く範囲)。凹みの暗さと鏡面もこちら側 |
| 混ぜ方 | Form Shading の割合で混ぜる (既定 0.25、Cel Hard Light は 0.6、Cinematic は常に 1 で原典どおり) |
| 深度の時間方向のならし | Depth Stabilize。PreRender で深度レイヤーを前後 ±1・±2 フレームの時刻でも取り出し、画素ごとに中央値を取る。1〜2 フレームだけ飛び出す値 (細い髪の毛先が背景になる等) が消え、一定の速さで動く物の輪郭は今のフレームの位置のまま |
| リムの作り方 | 撮影の定番「マットを光源の方へずらして引く」を深度でやる。画素から光源の向き (逆光なら Rim Spread で絞った 8 方向も) へリムの幅の中で 6 点ずらし、ずらした先が十分奥 (物の外) になる割合を帯の下地にする (輪郭のすぐ内側で 1、幅の奥で 0)。下地を幅 × 0.3 の箱形でぼかし、ぼかす前の下地が無い画素は消す (輪郭の外へにじませない)。さらに、すぐ後ろ 3px 以内に線画があり、前へ進むと線を越えずに深度が落ちる画素 (深度の境目が線画より外へずれたすき間) は帯にしない。人物の輪郭線の外へリムを出さないため (線画の無い輪郭は深度の境目のまま)。最後に光源の色・強さ・距離を付ける。以前は 1 画素ずつ輪郭を探して距離を測っていたため、判定が少し揺れると帯の幅が段になり、ビーズのように切れて汚く見えた |
| 影色の判定 | 撮影寄りの当たり具合を主にし、立体的な当たり具合は Form Shading の 2 乗の割合でだけ混ぜる |

測定 (効果のフレーム間の変化の平均。静止部分は元の絵が動いていない画素だけ):

| 設定 | 全体 | 静止部分 |
|---|---|---|
| 以前 (立体的) | 0.0080 | 0.0034 |
| 撮影寄り 0.25 + 時間方向 (新しい既定) | 0.0049 | 0.0016 |
| 撮影寄り 0 + 時間方向 | 0.0046 | 0.0014 |
| 上 + リムを線画に合わせる・影色の判定・中央値 | 0.0048 | 0.0015 |

残りの多くは素材が動いている所 (髪やスカートの揺れ) の近くで、光が動きに付いていく分 (tools/harness/flicker_map.py で場所を見る)。
深度を全フレーム固定すると静止部分は 0.0006 (素材の圧縮ノイズなどに効果が付いていく分)。
素材の色を手がかりに深度を ±8 フレームでならす試し (tools/temporal_depth_test.py) は効かなかった (静止部分の深度はもともと揺れていない)。

### GPU 版 (v2.2、2026-10-08)

照明の計算は RelightCore.h にまとめ、関数はすべて CPU と GPU (CUDA の __host__ __device__) の両方で動く。
全体の手順は CPU 版 (RelightAE.cpp の RenderFrameCPU、作業スレッドで行ごと) と GPU 版 (RelightGPU.cu の RelightGPU_Render、カーネルで 1 画素・1 マスずつ) がそれぞれ持ち、同じ関数を呼ぶ。

| 項目 | 内容 |
|---|---|
| AE とのやりとり | GlobalSetup で PF_OutFlag2_SUPPORTS_GPU_RENDER_F32。PF_Cmd_GPU_DEVICE_SETUP は CUDA のときだけ GPU 可と返す (DirectX / OpenCL / Metal は CPU 版)。PreRender で Use GPU がオンなら PF_RenderOutputFlag_GPU_RENDER_POSSIBLE。PF_Cmd_SMART_RENDER_GPU では入力・出力・深度などのワールドが GPU のメモリ (BGRA float) で渡るので、PF_GPUDeviceSuite1::GetGPUWorldData の場所をそのまま使う |
| 画像の読み取り | RLImage (ARGB 8 / 16 / float、BGRA float、1 チャンネル float) を CPU と GPU で共通に読む |
| 輪郭からの距離 (膨らみ) | CPU は 2 パスの距離変換、GPU は隣 8 マスから 1 歩ずつ広げるのを VOLUME_RADIUS 回。膨らみに効く範囲では同じ値 |
| 作業領域 | GPU のメモリは使い回し (cudaMalloc はフレームごとに呼ばない)。PF_Cmd_GPU_DEVICE_SETDOWN で手放す |
| 光の玉の隠れ具合 | 光源ごとに 1 回だけ GPU で求め、CPU へ戻して画素の計算に渡す |
| 速さ | 1344x768 で GPU 0.6〜1.3 ms (CPU 40〜50 ms)。tools/harness/compare_gpu.py で CPU 版との差を確かめる (8bit で最大 1 段) |

### AE 側の都合

- 入力は premultiplied。非乗算に戻して計算し、Mix とマスクで元の色と混ぜてから掛け戻す。
- 既定は sRGB 表示色として扱う（ガンマ 2.2）。リニア作業空間なら Input Is Linear。
- パスは 16bit PNG。色管理なしで値がそのまま届く。EXR は Preserve RGB が必要で、付けられない場合は Pass Encoding = sRGB (decode)。

## 4. 既知の限界

| 限界 | 対応 |
|---|---|
| 元映像に焼き込まれた影は消えない（暗くして上から光を足す方式） | 大きく描き直す用途は第二段階（生成モード） |
| 深度の背景が遠い壁として扱われ、大きな落ち影が出ることがある | Shadow で調整。Mask Layer で範囲を限定 |
| 光源は 3 灯まで | 足りなければ PRESETS と RELIGHT_MAX_LIGHTS を増やす（落ち影の計算が光源の数だけ増える） |
| リムと膨らみは深度の輪郭に頼る | 深度モデルの輪郭は少し太るので、リムが輪郭の外へ 1〜2 px はみ出すことがある。Rim Width を狭める |
| 線画の保護は暗さで判定 | 色トレス（色の付いた線）は Line Threshold を上げる。暗い小物も線として残る |
| CPU 計算 | 勾配・凹み・落ち影は 448 マスの格子で先に計算し、画素では補間する。16 スレッドで 1080p 約 31 ms、4K 約 66 ms。さらに必要なら GPU 化 |
| 深度推定の速度と VRAM | 480x864・192 フレームで推論 4.2 秒、PNG 書き出し込み約 10 秒。VRAM ピーク約 11GB。元の PyTorch (fp32) は 9.9 秒 |
| CUDA の DLL を ComfyUI と PyTorch の場所から借りている | 配布するなら ONNX Runtime GPU と CUDA / cuDNN の DLL を同梱する |
| 時間伸縮・タイムリマップしたレイヤー | 深度レイヤーは素材と同じ開始時刻・フレームレートで置くだけ。伸縮は未対応 |
| AE 内でのフレーム書き出しと結線を未確認 | ユーザーの AE で確認する（AE を勝手に起動・終了しない） |

## 5. 検証方法

- `tools/harness/relight_cli`: RelightAE.cpp をそのまま取り込み、AE なしで 1 フレームを描く。
  `python tools/harness/run_cli.py --src <画像> --depth <深度 PNG> --out <出力> -- lx=<x> ly=<y>`
- `tools/harness/compare_presets.py`: 1 フレームをプリセット全部、または `--sets "名前=key=value ..."` の設定で描いて並べる。`--crop` で切り出し
- `tools/ae_test.jsx` などの AE スクリプトは、ユーザーの AE に転送されるため、使う前に確認する。
